### 이슈
1. 워크플로를 넣어 저장하면 느리고, jpg에는 워크플로가 들어가지 않습니다.
   * ASIS: WAS `Image Save`의 화면 시간은 webp 0.229초, jpg 0.109초이고, jpg에는 워크플로가 없습니다.
   * TOBE: jpg에 워크플로를 넣고, 파일을 끌어다 놓으면 복원합니다.

### 원인 분석
1. WAS 노드는 저장마다 기록 파일의 경로 38,510개를 확인하고 파일을 읽고 씁니다(약 93 ms).
2. webp 인코딩은 125 ms로 jpg 4 ms보다 깁니다.
3. 프런트엔드는 png와 webp에서만 워크플로를 읽습니다.

### 솔루션
1. 워크플로가 들어간 jpg를 기록 작업 없이 빠르게 저장하는 `FastImageSave` 노드를 추가했습니다.
   - 메타데이터는 키별 JSON 문자열을 zlib으로 압축해 APP15 세그먼트에 넣고, 크면 여러 세그먼트로 나눕니다.
   - 번호는 폴더 목록 대신 파일 존재 확인으로 찾고, 덮어쓰지 않습니다.
   - 파일 이름은 `<prefix>_00001.jpg` 형식이고, `images` 출력은 입력을 그대로 전달합니다.
2. 저장한 jpg를 끌어다 놓으면 워크플로를 복원하고, `%date:...%`를 바꾸는 프런트엔드 확장을 추가했습니다.
   - `web/js/image_save.js`
